- 2026-11-25 | Whisper gets a vocabulary prompt: `voice.stt_vocabulary` plus the card and set names in the listing pool. | Without it Whisper wrote "Pocaccia", "MuteWO", "Blast Toys" and "hollow" for Pikachu, Mewtwo, Blastoise and holo.

- 2026-11-25 | The Edge-TTS limit (`limits.tts_timeout_seconds`, 3 s) is the longest wait for the next piece of audio, not for the whole reply. | Whole replies take 1.8–6.6 s to arrive while audio keeps coming; the limit is there so a stalled or refused Edge-TTS doesn't stop the demo.
- 2026-11-25 | Replies are spoken a sentence at a time, each synthesized while the one before it plays. | The first sentence is ready in 0.7–1.6 s instead of 1.8–6.6 s for the whole reply.
- 2026-11-25 | The filler starts when EVALUATING starts, as planned, even though INTENT (2.3–4.6 s) comes before it. | Keeps the H5 measurement as preregistered; an earlier filler is a possible change to test later.
- 2026-11-25 | The voice chat runs without the LLM cache. | Its timing log must time real calls.
- 2026-11-25 | The greeting is "Hi! I'm your AI card-shopping assistant. How are you doing today?" | The asked-for opening plus the AI disclosure Plan Section 6 requires at the start of a session.
- 2026-11-25 | The read-back is built by code from the parsed query, not written by the LLM; a plain yes is read by code. | Its numbers must be exactly the ones the search will use, and a yes shouldn't wait for an LLM call.
- 2026-11-25 | The graph reads the request back only when the caller asks for it (`confirm_first`, set by `ChatSession`); price checks never get one. | The tests, the demo and the evaluation runner call the graph directly and must run as before.
- 2026-11-25 | Live search: 100 listings per request (`merchant.live_limit`), and the request picks only from those fresh listings. | Gaurav asked for live testing at 100 per request; 500 would cost about $6.20 and take minutes per request.
- 2026-11-25 | `--replay FILE` replays a saved scrape through the live path. | Testing the live path for free; $3.64 of Apify credit is left this month.
- 2026-11-25 | The 5-part score (deal, condition, trust, convenience, confidence) replaces Plan v2's formula by default; the plan formula stays as `scoring.method: plan`. | The plan's price part compares with the budget, so it can't tell a bargain from a normal price. Gaurav didn't pick an option; this was the recommended one.
- 2026-11-25 | The seller part of the score comes from listing signals (photos, description, public meetup, listing age, pending) and the scam risk. | Facebook Marketplace returns no seller ratings; eBay's would need its production API approval. Gaurav didn't pick an option; this was the recommended one.
- 2026-11-25 | A price under 60% of market gets a neutral deal part (0.5) and no price reason. | Such a price is a scam signal, scored by the risk check; rewarding it put a flagged listing first in the replay run.
- 2026-11-25 | Flag explanations may only claim red flags found in the listing; retrieved entries are passed as background. | The explanation LLM claimed "borrowed photos" and "reproduction" that weren't in the listing.
- 2026-11-25 | $1 listings are dropped like $0 ones (`ingest.placeholder_max_price`). | 8 of the 78 scraped listings were $1 "make an offer" posts.
- 2026-11-25 | The printed set size picks the set when it is unique; otherwise TCGdex is asked which set with that size has this card at this number. | Sizes are often shared (182: Paradox Rift and Destined Rivals; 132: four sets), and the LLM guessed sets wrong.
- 2026-11-25 | A rule-based title pre-filter drops graded slabs, lots, sealed product, non-English cards and (live) listings that never name the card before the LLM; it errs on keeping. | On the 100-listing scrape it removed 21 of 65 listings with no wrong drops; for a live Charizard search, 47 of 65.
- 2026-11-25 | Identification calls run 4 at a time, and identified cards are cached by model and listing text. | Identification was 36–47 of the 56 seconds before an answer; a repeat search shouldn't pay for it again.
- 2026-11-25 | Replies are 2–3 short casual sentences (about 50 words); the sample-data note is said once per conversation. | Gemini's replies ran 15–25 seconds of speech and repeated the note every time.
- 2026-11-25 | The web page is served by Python's own `http.server` with server-sent events, and the page is one hand-written HTML file with no build step. | No new dependency, nothing to compile, works offline; one buyer and one browser tab need nothing more.
- 2026-11-25 | The page shows the seller's city, distance, listing date and listing signals, not the seller's name. | The Apify actor's output has no seller field at all (Facebook hides seller names from logged-out scrapers); other actors need Facebook login cookies.
- 2026-11-25 | Listing links are kept only in the running system's memory (the live search summary) for the page, never written to a file. | The page needs a way to open each listing; Section 14 still holds for everything stored.
- 2026-11-25 | Card rarity, picture and TCGplayer product id are fetched from TCGdex only for the cards on the page, after the reply, and cached in `.cache/cards`; `data/prices.json` is unchanged. | Keeps the answer as fast as before and doesn't rewrite the price cache.
- 2026-11-25 | In voice mode the page follows along but takes no typing. | One input at a time keeps the conversation and the speech in order.
- 2026-11-25 | `ChatSession.send`'s `on_task` callback gets a third argument with the progress details (counts, search term). | The page shows the numbers; the voice chat ignores them.
- 2026-11-26 | The page's microphone is click to talk, click again to send (Esc cancels), not automatic speech detection. | The same push-to-talk choice as the voice chat (Section 6): no false starts from room noise.
- 2026-11-26 | The page's recordings are transcribed on the server with the voice chat's `Transcriber`, not by the browser's speech recognition. | Same accuracy and card-name vocabulary as the voice chat; the browser's recognizer doesn't know card names and differs between browsers.
- 2026-11-26 | Spoken turns are read aloud in the voice chat's Edge-TTS voice (`/api/speech`, sentence by sentence); the browser's own voice only if that fails. Typed turns stay silent. | One voice for the whole system; talk and you hear, type and you read.
- 2026-11-26 | The benchmark is synthetic for now (100 listings, 50 queries, 5 memory scripts); the real snapshot joins after its hand check. | An answer key needs listings whose truth is known; the snapshot isn't hand-checked yet.
- 2026-11-26 | Dev traps use the red-flag knowledge base's wording; test traps use new wording. | So the test split measures whether scam detection generalizes, not whether it memorized its keywords.
- 2026-11-26 | The answer key comes from an oracle that only uses the ground truth and its own weights (value, condition, visible safety), never the system's risk or listing score; acceptable picks are within 0.08 of the best. | Avoids a circular test (the plan review's concern).
- 2026-11-26 | One clean listing per printing is a real deal (about 85% of market, meetup, photos), and the collector oracle weights condition 0.75. | The first key made honest-but-odd decoys the right answer almost everywhere.
- 2026-11-26 | The single-agent baseline is one LLM call that sees every listing with the same tool outputs the four agents compute, plus the same scripted clarify answer. | Same information and tools, so the comparison isolates the architecture.
- 2026-11-26 | During an evaluation run the model has no quota fallback, and 3 LLM errors in a row stop the run. | A run that silently switched models would mix results.
- 2026-11-26 | Latency statistics use only rows whose LLM calls were all real (not cached). | A cached call takes no time.
- 2026-11-26 | The judge is gpt-oss-120b on Groq and doesn't see the variant or the AI notice at the start of a reply. | Another model family than the agents' Gemini; the notice is the same for every variant. Its scores count only after the 20-reply human check.
